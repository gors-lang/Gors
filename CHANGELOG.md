# Changelog

## 1.0.0-alpha.2

- `write_text(path, text)` записывает файлы в обоих основных бэкендах и
  в bootstrap. `gors-bootstrap emit <file> -o <output.c>` сохраняет C напрямую.

- Bootstrap-анализатор и генератор C поддерживают `Result<T, E>`,
  `Ok` и `Err` и проверяют полноту `match`.
- `read_bytes` читает файл в двоичном режиме. `wc.gors` собирается
  bootstrap-компилятором и проверяется на пустых, двоичных и отсутствующих файлах.

## 1.0.0-alpha.1

- Bootstrap-компилятор поддерживает `[]int`, `[]bool` и `[]string`,
  включая литералы, обход, замену элементов и `push`. Срезы `[]int` и
  `[]bool` создают независимую копию.
- В архивы Linux и Windows добавлены автономный исходник `gors-bootstrap.c`
  и примеры для проверки. CI публикует теги с суффиксом как предварительные релизы.

- Генератор C на GoRs поддерживает строки с явной длиной и аргументы
  `main(args: []string)`, включая индексацию и обход через `for`.
- Добавлен первый генератор C23 на GoRs. Команда `gors-bootstrap emit`
  компилирует подмножество с `int`, `bool`, функциями и циклом `while`.
  Сквозные тесты собирают сгенерированный C и сравнивают результат с текущим бэкендом.
- Добавлен экспериментальный анализатор на GoRs для однофайловых программ.
  Он проверяет локальные имена, вызовы, базовые типы, слайсы и возврат из функций.
- Парсер на GoRs строит деревья тел функций и методов. Добавлены тесты формы
  дерева, синтаксических ошибок и разбора корпуса на обоих бэкендах.
- Исправлено разрешение имён в выражениях `for` и границах срезов в файловых модулях.
- Go-бэкенд сохраняет временный слайс в локальную переменную перед обходом через `for`.
- Парсер на GoRs разбирает объявления структур, сигнатуры функций и методов.
  Тела функций пока представлены байтовым диапазоном.
- Go-бэкенд использует проверенные типы полей структур, включая `Option` и `Result`.
- Лексер на GoRs возвращает исходные байты и структурированные токены через
  `scan`. Первый модуль парсера использует этот API для разбора начальных `import`.
- Добавлен лексер на GoRs в `bootstrap/lexer`. Он печатает типы токенов,
  позиции и байтовые диапазоны. Тесты сравнивают его с Go-лексером на обоих бэкендах.
- Исправлено освобождение заимствованного значения при чтении через разыменование
  в C-бэкенде. Перенос владеющего значения через `*` теперь отклоняется.
- `read_bytes(path)` читает двоичные файлы, `eprintln` пишет в stderr,
  а `main -> int` задаёт код завершения. Пример `examples/wc.gors` использует
  все три возможности.
- `fn main(args: []string)` получает аргументы командной строки в обоих бэкендах.
  Команда `gors run` передаёт программе всё после `--`.
- Срезы копируемых элементов создают независимое хранилище в обоих бэкендах.
- Одинаковая диагностика границ срезов строк и слайсов в C и Go.
- Срезы некопируемых элементов отвергаются с `E183`, предотвращая двойное
  освобождение при поверхностном копировании в C.
- Исходное значение защищено от изменения и перемещения во время вычисления
  границ среза. Пустые срезы в C не используют арифметику нулевого указателя.
- Уточнены документация и комментарии о возврате ссылок с выводом времени жизни.

## 0.1.0

- Локальные файловые модули: `import alias "file.gors"`, `alias::name`, `pub`.
- Исчерпывающий `match` для `Option` и `Result` с переносом владения в ветку.
- Освобождение временных значений, остатка частично перемещённых структур,
  заменяемых значений и промежуточных аргументов при раннем выходе через `?`.
- Проверки ссылок и их псевдонимов, аргументов вызова, методов, циклов и ветвлений;
  явные ограничения v0.1 вместо несуществующей системы времён жизни.
- Диагностика с исходным текстом, подчёркиванием, связанными местами и подсказкой.
- Исправления обоих бэкендов для короткого замыкания, условий циклов и `?` с
  отличающимся типом успешного результата. Одинаковая ошибка проверки границ.
- `gors --version`, спецификация языка, CI Linux/Windows и упаковщик архивов
  с SHA-256. Релиз и Git-тег автоматически не публикуются.
